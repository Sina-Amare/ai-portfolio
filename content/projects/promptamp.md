# PromptAmp

## What PromptAmp is
PromptAmp is a browser extension Sina built (repo github.com/Sina-Amare/promptamp) that turns a rough draft into an engineered prompt inside any text field on any website — ChatGPT, Midjourney, a code assistant, anywhere. A small ✦ button appears in the corner of the field; pressing it rewrites the draft using the user's own API key, shows the result next to the original, and replaces the text only when the user accepts. It is live on Firefox Add-ons (AMO), with Chrome and Edge builds shipping from the same codebase. The tagline: "The prompt amplifier — your keys, any site."

## The problem it solves
Most people type half-formed requests into AI tools ("make it faster and add validation") and get mediocre results, while prompt-engineering advice lives in blog posts nobody applies mid-task. PromptAmp moves that skill into the text field itself: one tap turns the rough thought into a structured, precise prompt, in place, without switching tabs or pasting into a separate tool. It works with drafts written in any language — the engineered prompt comes back in the draft's own language, or the user can force an output language: the options page offers fourteen (English, Persian, Arabic, Spanish, French, German, Portuguese, Italian, Turkish, Russian, Hindi, Chinese, Japanese, Korean) plus a free-text "Other", so a Persian draft can become a polished English prompt. One deliberate exception: prompts aimed at image and video generators default to English, because those models are trained on English captions — unless the user asks otherwise.

## Keeps what you paste, sharpens only the ask
A core design rule: pasted content is sacred. If a draft contains code, a log, or a document plus a rough request, PromptAmp reproduces the pasted content byte-for-byte and engineers only the request around it. Your code never comes back subtly rewritten — only the ask gets sharpened.

## The insertion engine (working in every text field)
Writing text into arbitrary websites is the hard engineering problem, because `el.value = text` updates the pixels but not the host editor's model — React re-renders the old text back, and ProseMirror's document desynchronises from its DOM. PromptAmp has a six-tier insertion engine — exec-command, native setter, contenteditable, paste simulation, a main-world editor bridge, and clipboard as the last resort — and every tier writes through an input-event path rather than assigning to the DOM directly, so the host editor's model and the user's native Ctrl+Z history stay intact. The main-world bridge talks to rich editors over a validated postMessage channel from the extension's isolated world.

## Providers: your keys, a failover chain, no shopping for compliance
PromptAmp is strictly BYOK (bring your own key): OpenAI, Anthropic, Google Gemini, Groq, OpenRouter (one-click PKCE OAuth sign-in — the extension never sees your password), local Ollama and LM Studio, plus any custom OpenAI-compatible endpoint (Together, DeepSeek, Mistral, a self-hosted vLLM, a LiteLLM proxy). Because the category converged on one wire format, "support everything" is a base-URL field rather than an abstraction layer — only two request shapes exist in the code, OpenAI-compatible and Anthropic's Messages API, with every other provider difference living in a data table. The provider list order is a failover chain: failures that belong to one credential (bad key, quota, host down) hand over to the next connection, while failures that belong to the draft or the user stop the chain — and a model's refusal deliberately does not hand over, because walking down a list of models until one complies would be shopping for a permissive model.

## Private by construction
There is no PromptAmp server — requests go from the browser straight to the chosen provider. No telemetry, no analytics, no accounts. API keys live in the browser's storage.local and never storage.sync (syncing would replicate them through the browser vendor's servers). Host permissions are narrow: a fixed list of provider API hosts, and for a custom endpoint, permission for exactly that one host, requested on the click that saves it. Enhancement history is local and can be cleared or disabled. A soft spend cap watches per-request cost estimates and warns before a runaway bill.

## Tested like an app, not a script
The extension ships with a Vitest unit suite (14 test files covering the insertion engine, provider adapters, failover chain, storage, streaming, and cost tracking) and a Playwright end-to-end suite (12 spec files that drive the built extension in a real browser — insertion into live editors, failover, options, accessibility, and recovery flows), plus CI. The screenshots in the README are generated by a dedicated Playwright config, so they always match the shipped UI.

## PromptAmp tech stack
TypeScript throughout, built on WXT (Manifest V3, one codebase producing Chrome, Firefox, and Edge builds), vanilla-TS popup and options pages with no framework, Vitest for unit tests, Playwright for end-to-end tests, pnpm, and MIT-licensed. Published on Firefox Add-ons; Chrome and Edge load the same build unpacked. It's the project that shows Sina's client-side depth — DOM internals, browser extension security model, OAuth PKCE — alongside the same provider-failover thinking as his backend work.
